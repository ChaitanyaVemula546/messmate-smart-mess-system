# Run and deploy your own MessMate

No production deployment or paid resource has been created. All hosting options below are optional; source ownership does not depend on a subscription.

## Required configuration

| Variable | Use |
|---|---|
| DATABASE_URL | PostgreSQL in production; pglite:// directory only in development |
| AUTH_SECRET | At least 32 random characters; HMAC key for session/device token hashes |
| APP_URL | Exact browser origin, e.g. your final HTTPS website origin |
| API_PORT | API listening port, default 4000 |
| API_HOST | 0.0.0.0 for LAN development; use 127.0.0.1 behind a local HTTPS proxy |
| API_INTERNAL_URL | API origin used by the Next.js same-origin proxy |
| NEXT_PUBLIC_API_BASE_URL | Keep /api for the web proxy unless deliberately configuring direct CORS |
| EXPO_PUBLIC_API_BASE_URL | Public API base ending /api, reachable from the phone |
| DEMO_PASSWORD | Development seed only; generated by pnpm run setup |
| DEVICE_API_SECRET | Reserved compatibility placeholder; never acts as a shared device auth bypass |
| NODE_ENV | production for deployed API/web |

The root `.env` is loaded by API/database tools. Next.js uses its own environment or `apps/web/.env.local`; set API_INTERNAL_URL in the web deployment environment if the API is not at the development default. Expo reads `apps/mobile/.env`. Never place server secrets in NEXT_PUBLIC_ or EXPO_PUBLIC_ variables.

## Local production check

Stop the development API before using the same PGlite directory. Build commands do not require database access.

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

For a real production run use PostgreSQL, apply migrations and set the environment securely. `pnpm --filter @messmate/api start` runs the bundled API; `pnpm --filter @messmate/web start` runs the built Next.js server. Keep both processes managed with restarts and place them behind HTTPS. The Next.js proxy and APP_URL must agree about the browser origin.

## First production administrator

Apply database migrations first. Inject BOOTSTRAP_ADMIN_EMAIL, BOOTSTRAP_ADMIN_NAME and BOOTSTRAP_ADMIN_PASSWORD securely in the process environment, then run `pnpm admin:bootstrap`. It refuses to run when an administrator already exists. Clear the one-time bootstrap environment values afterward. No demo database seed is needed. Use the application to create mess managers and students.

## Optional Docker Compose PostgreSQL

A `compose.yaml` definition provides PostgreSQL with a health check and named data volume. Provide your own private POSTGRES_USER, POSTGRES_PASSWORD and POSTGRES_DB values before `docker compose up -d`. It binds to localhost only. It is a local development aid, not an Internet database service. Docker was not installed in the build environment, so this configuration needs local verification.

## Optional hosting

Deploy the API to a service capable of a long-running Node process and connect it to PostgreSQL. Deploy the Next.js app alongside it or to a compatible Next.js host. If using Vercel later, only the web app is placed there and API_INTERNAL_URL points to the deployed shared API. The API is not silently converted into a separate backend. Configure one production database for all clients. Free-tier eligibility, limits and provider policies must be checked at the time you choose hosting. Do not enable billing to follow these instructions.

## Manual private GitHub upload

Create an empty PRIVATE repository in your own GitHub account, named `messmate-smart-mess-system`. Do not initialize it with separate starter files if you plan to push this Git history. Copy its actual clone URL; no repository URL is assumed here.

```bash
pnpm secrets:check
# If the exported folder has no .git directory:
git init -b main
git add .
git commit -m "Build MessMate web, mobile and shared API"
# Replace the placeholder with the private repository's actual URL:
git remote add origin YOUR_PRIVATE_REPOSITORY_URL
git push -u origin main
```

Review `git status` and staged filenames before committing. `.env`, `.demo-credentials.json`, `.data`, firmware private configs and build outputs must not be tracked. If restoring the optional source-history bundle from the archive, clone that bundle into a directory instead of reinitializing Git. A GitHub login is only needed for the optional push, never for local development.

## Example Linux service configuration

`deployment/` includes API/web systemd units and an Nginx HTTPS proxy example. Replace the example domain, certificate paths and Node binary path. Create the dedicated `messmate` OS account, place the built source and installed dependencies at `/opt/messmate`, and provide private environment files under `/etc/messmate` with restricted permissions. API configuration must include NODE_ENV=production, API_HOST=127.0.0.1, a real PostgreSQL URL, AUTH_SECRET and the exact HTTPS APP_URL. Web configuration needs NODE_ENV=production and API_INTERNAL_URL=http://127.0.0.1:4000 at build and runtime. Stop services before migrations when changing schema. Validate Nginx/systemd on the target host before enabling these examples; they were not executed here.

Use a certificate your devices can validate and set the corresponding root CA in their private config. The API refuses a non-HTTPS production APP_URL. Keep ports 3000/4000 and the database inaccessible from the public Internet; the API_HOST setting defaults to 0.0.0.0 only for local phone development.
